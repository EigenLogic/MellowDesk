# 小桌伴 MellowDesk：产品设计

## 1. 产品定义

小桌伴（MellowDesk）是一款安静待在菜单栏、帮助用户在工作时照顾身心状态的开源 macOS 桌面伴侣。产品用一条统一时间线轮换起身活动、日常补水、“颈间（NeckEase）”微运动和提肛跟练，解决工作投入后忘记离开椅子、补水与活动的问题，同时避免多套提醒轮番打断。

产品闭环只有四步：

```text
统一节奏提醒 → 起身 / 补水 / 颈肩 / 提肛 → 本地完成记录
```

当前版本不做账号、云同步、社交排名、连续坐姿监控、饮水量处方、医疗问卷、疾病诊断、自训练模型或健康分数。午餐和外卖提醒属于后续模块。

## 2. 目标用户与场景

- 长时间使用 MacBook 或外接显示器的知识工作者。
- 希望获得明确、低打扰活动提示，但不想佩戴额外设备的用户。
- 主要场景是工作日 09:00–18:00，每 50 分钟收到一项工作间歇提醒，自主开始或推迟。

## 3. 核心用户流程

1. 首次启动后，App 常驻菜单栏并请求通知权限。
2. 单一计划按“起身活动 → 起身补水 → 颈肩微运动 → 提肛跟练”轮换；同一时刻最多一张持久提醒卡。
3. 起身/补水进入两分钟轻活动引导；完整完成提肛跟练后同样保存一条轻量本地记录。
4. 颈肩活动由用户主动开始，之后才请求并开启摄像头。
5. 训练前正视摄像头约 2 秒，建立个人中立位；每项动作先做一次不计数的小幅适配动作并回正。
6. App 逐项演示动作、提示当前方向并自动计次；摄像头不可用时可手动确认。
7. 当前项目完成后保存本地记录并推进轮换；推迟或关闭不会推进到下一项。
8. Sparkle 默认每天检查新版本并在后台下载；签名验证通过后，用户可选择“安装并重启”或“稍后”，后者会在退出小桌伴时安装，全程不离开 App。

## 4. 颈肩动作方案

| 动作 | 口令 | 剂量 | 自动识别信号 |
|---|---|---:|---|
| 左右缓慢转头 | 坐直、肩膀放松，转到舒适范围，停留后回正 | 每侧 4 次 | yaw |
| 左右轻柔侧屈 | 面向前方，耳朵向同侧肩膀方向靠近，不抬肩 | 每侧 3 次 | roll |
| 轻柔低头并回正 | 下巴缓慢向胸前靠近，停留后回到自然中立位 | 5 次 | pitch |

每次有效重复必须包含：中立位、正确方向、达到相对个人中立位的保守阈值、保持至少 300ms、全程可见地回到中立位并保持至少 300ms。转头和侧屈使用固定保守阈值；轻柔低头根据本次示范的稳定峰值自适应到 5–8°。这些都是摄像头识别阈值，不是医学活动度或动作剂量。

这些次数是首版产品剂量，不是治疗处方。用户只需在舒适范围内完成；系统识别的是镜头中的运动方向与节奏，不评价椎体状态、肌肉发力或医疗意义上的“标准度”。

## 5. 主要界面

### 菜单栏面板

- 今日颈肩、喝水、起身和提肛分类完成次数。
- 下一项活动、提醒时间或暂停状态。
- 手动开始颈肩、喝水打卡、起身活动和暂停到明天。
- 完成记录、设置、退出。

### 状态栏跟练面板

- 开始前说明三项动作、预计时长与单句停止提示。
- 左侧动画、动作口令、当前方向和次数环。
- 右侧镜像摄像头预览、跟踪状态、实时阶段提示。
- 活动态保持悬浮在其他 App 前面；点击状态栏图标可收起并恢复同一进度。
- 重新校准、暂停、切换手动计次和跳过本次；跳过不写完成记录。
- 完成页展示三项结果及本次用时。

### 完成记录

- 今日三类完成情况；颈肩可显示用户设置的记录目标。
- 近 7 天、近 30 天总完成次数和按活动筛选的趋势。
- 连续有记录天数。
- 7 / 30 天柱状趋势和最近六次完成。

### 设置

- 统一计划、提醒间隔、工作日、开始/结束时间、颈肩记录目标。
- 声音、登录启动、暂停/恢复。
- 默认开启“自动下载并安装更新”，也可手动“现在检查”；更新在后台下载并完成签名验证后，提供“安装并重启”或“稍后”，不跳转网页。
- 通知状态、摄像头系统设置入口、清除历史。

## 6. 容错体验

- 无脸：暂停计数，提示回到画面。
- 多人：暂停计数，不在不同面部之间切换。
- 遮挡超过 500ms：放弃当前未完成的一次，要求回中。
- 摄像头拒绝、受限、占用或缺失：弹出原因并允许手动计次。
- 识别不到较小活动范围：不催促用户做更大幅度，允许手动完成。
- 用户忽略通知：常驻进程自动安排下一条，不中断提醒链。

## 7. 数据与隐私

`workout-history.json` 保存颈肩训练汇总：存储版本和 session 列表；每个 session 包含 ID、开始/结束时间、状态、内容版本、是否实际使用摄像头，以及每个动作的 ID、目标次数、完成次数和完成模式。`wellness-history.json` 保存起身/喝水/提肛活动类型、完成时间、随机记录 ID 和用于幂等去重的本地提醒来源 ID。用时由开始/结束时间计算，不另存一份。

不保存：视频、照片、音频、人脸特征、逐帧头部角度、身份信息或云端分析事件。训练结束、跳过或状态栏跟练面板收起后立即停止摄像头并拆除捕获输入输出。

网络只用于读取 raw GitHub 上的签名 appcast，并下载其中指向的 EigenLogic/MellowDesk GitHub Release ZIP。更新偏好和状态由 Sparkle 直接保存在标准 UserDefaults，不写入训练历史。Sparkle 系统画像上报已关闭；不发送账号、用户设置、健康记录、摄像头数据、分析或遥测。

## 8. 验收标准

- 三动作均可在摄像头和手动模式下完成完整流程。
- 正常光线、单人正脸环境中，一组动作计数误差不超过 ±1。
- 单帧抖动、未达到阈值、未回中和长遮挡不会产生误计。
- 摄像头权限拒绝后仍可完成并保存训练。
- 关闭或完成训练后系统摄像头指示灯熄灭。
- 忽略一次通知后，下一提醒仍按工作时段继续。
- 起身、补水、颈肩和提肛按单一计划轮换，推迟不换项，完成或明确跳过后推进。
- 起身/补水关闭时不误记完成；喝水提示不要求固定毫升数。
- 今日、7 天、30 天记录正确合并训练 session 与轻量活动完成记录。
- 除签名 appcast 和对应 GitHub Release ZIP 外无其他联网能力，磁盘中不存在任何图像或逐帧姿态数据。
- 默认每天自动检查并在后台下载更新；只有 EdDSA 与 Developer ID 验证通过后才提示安装，不打开浏览器。
- “安装并重启”立即完成替换和重启；“稍后”保留已验证更新并在退出 App 时安装，原设置和历史继续可读。

## 9. 本轮用户测试门槛

至少在一台真实 MacBook 前置摄像头上完成 [真人验收清单](TEST_CHECKLIST.md)，验证三轴方向、相对个人中立位的保守阈值、一组计数误差、权限拒绝与占用降级、窗口关闭后摄像头释放，才能完成本轮用户测试验收。合成序列自动测试不替代这项门槛。

## 10. 后续方向

- 扩展到更多用户、光线环境和 Mac 摄像头型号，持续校准 yaw / pitch / roll 识别表现。
- 午餐和外卖提醒；复用现有统一时间线，避免另建一套独立闹钟。
- 可选导出历史；不以此阻塞核心产品上线。

外部专业签审属于后续内容治理，不作为当前 MVP 实现或本轮用户测试的阻塞项；完成后应记录审校人、日期与逐动作来源映射。
